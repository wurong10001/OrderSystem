# Supabase 数据库配置

本文档对应当前 Worker 版本。请在 Supabase 控制台的 **SQL Editor** 中执行 SQL。数据库连接字符串、密码和管理员口令不要写入 Git。

## 一、新建数据库

如果项目使用全新的 Supabase 数据库，按以下顺序执行：

```sql
create extension if not exists pgcrypto;

create table public.app_users (
  id uuid primary key default gen_random_uuid(),
  username varchar(32) not null,
  username_normalized varchar(32) not null,
  salt char(32) not null,
  password_hash char(64) not null,
  permission smallint,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),

  constraint app_users_username_length
    check (char_length(username) between 3 and 32),
  constraint app_users_username_normalized_length
    check (char_length(username_normalized) between 3 and 32),
  constraint app_users_salt_format
    check (salt ~ '^[0-9a-fA-F]{32}$'),
  constraint app_users_password_hash_format
    check (password_hash ~ '^[0-9a-fA-F]{64}$'),
  constraint app_users_permission_value
    check (permission is null or permission in (0, 1, 2))
);

create unique index app_users_username_normalized_idx
  on public.app_users (username_normalized);

create table public.store_settings (
  id integer primary key default 1 check (id = 1),
  store_name varchar(100) not null,
  updated_at timestamptz not null default now()
);

create table public.menu_items (
  id bigint generated by default as identity primary key,
  item_code varchar(64) not null unique,
  name varchar(100) not null,
  description varchar(500),
  flavors text[] not null default '{}',
  price numeric(10,2) not null check (price >= 0),
  sort_order integer not null default 0,
  active boolean not null default true,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);

create table public.orders (
  id bigint generated by default as identity primary key,
  customer_name varchar(100),
  total_amount numeric(10,2) not null check (total_amount >= 0),
  status varchar(20) not null default 'pending',
  created_at timestamptz not null default now()
);

create table public.order_items (
  id bigint generated by default as identity primary key,
  order_id bigint not null references public.orders(id) on delete cascade,
  menu_item_id bigint not null references public.menu_items(id),
  item_name varchar(100) not null,
  unit_price numeric(10,2) not null check (unit_price >= 0),
  quantity integer not null check (quantity between 1 and 99)
);

insert into public.store_settings (id, store_name)
values (1, '我的店铺')
on conflict (id) do nothing;

alter table public.app_users enable row level security;
alter table public.store_settings enable row level security;
alter table public.menu_items enable row level security;
alter table public.orders enable row level security;
alter table public.order_items enable row level security;
```

## 二、已有数据库迁移

如果已经执行过旧版 `SUPABASE_AUTH_SCHEMA.md` 或 `ORDER_MENU_SCHEMA.md`，执行以下迁移。`permission` 的检查约束使用条件块，重复执行不会因约束已存在而失败。

```sql
alter table public.app_users
  add column if not exists permission smallint;

do $$
begin
  alter table public.app_users
    add constraint app_users_permission_value
    check (permission is null or permission in (0, 1, 2));
exception
  when duplicate_object then null;
end $$;

create table if not exists public.store_settings (
  id integer primary key default 1 check (id = 1),
  store_name varchar(100) not null,
  updated_at timestamptz not null default now()
);

alter table public.store_settings
  drop column if exists admin_username,
  drop column if exists admin_salt,
  drop column if exists admin_password_hash;

insert into public.store_settings (id, store_name)
values (1, '我的店铺')
on conflict (id) do nothing;

alter table public.app_users enable row level security;
alter table public.store_settings enable row level security;
alter table public.menu_items enable row level security;
alter table public.orders enable row level security;
alter table public.order_items enable row level security;
```

## 四、菜单字段迁移

如果菜单表已经存在，先执行以下迁移，再使用 `/admin/menu` 配置页面：

```sql
alter table public.menu_items
  add column if not exists item_code varchar(64);

alter table public.menu_items
  add column if not exists flavors text[] not null default '{}';

update public.menu_items
set item_code = 'item-' || id
where item_code is null;

alter table public.menu_items
  alter column item_code set not null;

create unique index if not exists menu_items_item_code_idx
  on public.menu_items (item_code);
```

`item_code` 是后台可修改的专属 ID，数据库主键 `id` 保持不变，避免影响历史订单。`flavors` 使用 PostgreSQL 文本数组保存口味选项。

`permission` 字段含义：

| 值 | 角色 | 权限 |
| --- | --- | --- |
| `NULL` 或 `0` | 普通用户 | 注册、登录和提交订单 |
| `1` | 管理员 | 登录后台，修改店名、菜品和价格 |
| `2` | 外卖员 | 角色已预留，当前接口暂未开放专用功能 |

将已有用户设置为管理员或外卖员：

```sql
update public.app_users
set permission = 1, updated_at = now()
where username_normalized = '管理员用户名';

update public.app_users
set permission = 2, updated_at = now()
where username_normalized = '外卖员用户名';
```

密码保存格式为：

```text
password_hash = SM3(salt + ":" + 用户密码)
```

其中 `salt` 是 32 位十六进制字符串，`password_hash` 是 64 位十六进制字符串。管理员登录接口只接受 `permission = 1` 的用户。

## 五、直连数据库和 Worker Secret

应用通过 `env.DATABASE_URL_DIRECT` 直连 Supabase PostgreSQL。不要把连接字符串写进 `wrangler.jsonc` 或提交到 Git。部署时配置 Worker Secret：

```bash
printf '%s' 'postgresql://<user>:<password>@<host>:6543/postgres' | npx wrangler secret put DATABASE_URL_DIRECT
```

管理员会话还需要配置 Secret：

```bash
printf '%s' '请替换为随机长字符串' | npx wrangler secret put ADMIN_SESSION_SECRET
```

## 六、当前接口

- `GET /menu`：显示店名和所有 `active = true` 的菜品。
- `GET /admin`：管理员登录页。
- `GET /admin/menu`：管理员菜单配置页，可修改店名、专属 ID、菜名、价格和口味选项。
- `POST /api/orders`：提交订单，格式为 `{ "customerName": "...", "items": [{ "id": 1, "quantity": 2 }] }`。
- `POST /api/admin/login`：管理员登录并设置 HttpOnly Cookie。
- `POST /api/admin/logout`：注销管理员会话。
- `PUT /api/admin/settings`：管理员修改 `{ "storeName": "..." }`。
- `GET/POST/PATCH/DELETE /api/admin/menu[/:id]`：管理员动态管理菜品和价格。

启用 RLS 后不要创建允许匿名客户端直接读写这些表的 policy。数据库操作由 Worker 通过 Hyperdrive 执行。
